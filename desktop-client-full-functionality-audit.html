Bugs — Must Fix

BUG 1   Own username missing from online users list

The server sends USER_JOINED to all other clients, never back to the joining client. MainFrame adds other users on USER_JOINED but never adds itself.

Fix: In MainFrame constructor, after chatPanel.init(...), add: chatPanel.addUser(username). One line.

BUG 2   Received files silently discarded

MainFrame.handleMessage() has no cases for FILE_META, FILE_CHUNK, FILE_COMPLETE — all fall into default → {} and are lost.

Fix: Add a FileReceiver helper (or inline in MainFrame) that:

1. On FILE_META: store fileId → ByteArrayOutputStream and metadata in a map.
2. On FILE_CHUNK: Base64-decode data, append to the buffer.
3. On FILE_COMPLETE: ask user where to save via JFileChooser, write bytes to file, show notification.

BUG 3   Received audio silently discarded

Same root cause as BUG 2 for AUDIO_META, AUDIO_CHUNK, AUDIO_COMPLETE.

Fix: On AUDIO_COMPLETE: reassemble bytes, write to a temp .wav file, append a clickable "▶ Play audio" notification in the chat panel that calls AudioPlayer.play() on a background thread.

BUG 4   Gemini AI completely unwired

GeminiChatManager is never instantiated. There is no input field or button to send a prompt. AI_RESPONSE is handled but can never arrive.

Fix: Add a row below the chat input (or a dedicated tab): a text field labelled "Ask AI..." and a "✦ Ask" button. Wire it to new GeminiChatManager(connectionManager).sendPrompt(text). The AI_RESPONSE handler already displays the reply.

BUG 5   Audio recording gives no UI feedback

The 🎤 Audio button triggers AudioManager.toggleRecording() but the button label never changes. The user has no way to know if recording has started, failed, or is still running.

Fix: MessageInputPanel should expose a method setAudioButtonLabel(String). AudioManager.toggleRecording() should accept a callback to update the label: "⏹ Stop" when recording, "🎤 Audio" when idle.

Warnings — Should Fix

WARN 1   No client-side username validation

Server pattern: [A-Za-z0-9_\-]{1,32}. Client sends without checking. Add in LoginFrame.attemptJoin():

if (!username.matches("[A-Za-z0-9_\\-]{1,32}")) { setStatus("Username: letters, digits, _ and - only, max 32 chars."); return; }

WARN 2   Audio 10 MB limit not checked before sending

Server rejects audio > 10 MB but desktop has no pre-check. After recorder.stop() in AudioManager: if (pcm.length > 10 * 1024 * 1024) { /* show error, return */ }

WARN 3   File transfer progress not shown

FileProgressListener is called from FileTransferManager but setProgressListener() is never called. Register a listener in MainFrame that shows a JProgressBar in a status bar while a transfer is active.

WARN 4   Audio errors go to stderr, not the UI

AudioManager catches all exceptions with System.err.println(). If the microphone is unavailable the user sees nothing in the chat window. Pass an error callback so the message appears as a notification.

WARN 5   No reconnect path after disconnect

After a disconnect the ExecutorService inside ConnectionManager is shut down permanently. Add a "Reconnect" button to the disconnect dialog that disposes MainFrame and opens a fresh LoginFrame.

Minor Issues

MINOR 1   No system look-and-feel

Add UIManager.setLookAndFeel(UIManager.getSystemLookAndFeelClassName()) in Main.main() before creating the LoginFrame — one line, makes the app look native on Windows.

MINOR 2   No executable fat JAR

pom.xml has no maven-shade-plugin. The server has one (produces chat-server.jar). Add a shade plugin to produce a standalone client-desktop.jar that can be distributed and run without Maven.
